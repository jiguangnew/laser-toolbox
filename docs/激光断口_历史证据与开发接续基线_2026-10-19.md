## 二、优先继承的真实成功/用户黄金参考
1. 2026-09-30 五毫米佛光寺：15 个嵌套 INSERT 旧流程未处理造成漏打；经递归分解、红线保护、局部检查，最终记录为“佛光寺模型零件排版补2_5mm_0.6断口修正版_v5.dxf”，7 处断口校正到整条直边几何中点；DXF 审计无错误/无残留 INSERT。注意此为历史图纸结果，不是本仓库 auto_tab 的独立批量通过证明。资料 https://docs.google.com/document/d/1VYPcNyHQovc_VMAK4nsINDZTsBTk_mEI8qsElEF-Kus/edit
2. 2026-10-01 用户亲手做的 3mm《最终版两个半张.dxf》是选位 GOLDEN 参考：历史助手复核数 248 处约0.7mm，白色完整直边中间、非弧线、红线保护；用户明确表示“大概都是这样”。以前 GPT 生成的 109、214 断口版本被用户否定，禁止当作黄金结果，也不得以总断口数定义成功。历史 https://drive.google.com/file/d/1njoSwd5C-QPZZ_5cL7Uu77ZYcKhxfXag/view
3. 旧 v1.0 实战手册固定项目值：3mm→0.7mm，5mm→0.6mm；禁弧线、槽底、真端点、真角点；平直完整边中心优先，长条两侧短边、平行两边支撑错位。白切透（ACI7）、红刻痕（ACI1）、绿内切/废料（ACI3）仅属当前项目模板，不代表任何客户都用同一配色。全圆零件没有合法直线应显式报异常，不套用 2025 圆上加口的旧规则。
4. 首版主脚本 auto_tab.py、规范化 normalize.py、拖拽 laserbox.py、断口实战手册.md、项目样例 test_input.dxf/test_spline.dxf 可复用；完整功能要以源代码及实际输出复测，不以 README 的“已实现”作结论。

## 三、不能继承的失败设计
A. 2025 旧 AutoCAD 插件《自动打断点软件开发》统一宽 0.7mm，曾以“新画一根线”表示断口，未真实在切割路径剪出连接，明确作废；旧圆形规则也未获新项目确认。https://drive.google.com/file/d/1mlSB0XNmvjGDlhONw-3esNrRRFKvYRoF/view
B. 3mm 自动版本把 CAD 单一短线段中点等同整块零件真实支撑边中点、忽略83条内圈，甚至在弧线兜底；用户明确否定。不得拿“audit=0”“总缺口214”替代人工标注对齐。
C. main 的 auto_tab.py 实际 dedup_and_clean 使用 NEAR_TOL=0.30mm 距离+投影判定并删除较短近邻线，能误删窄槽、薄壁、近邻真实双轮廓；TINY_LEN=0.30mm 直接删微线；group_parts/颜色继承存在需审计的几何语义风险。main build_output 为 R2010，项目手册要求 R2007。main normalize.py DXF 转换只覆盖部分实体，可丢失 TEXT/INSERT/SPLINE 和其它加工信息，并用兜底白色误映射。不能作为无人值守生产安全转换。
D. 10-14 候选 feat/duankou-20cases 的评审仅根据用户提交的算法/测试描述，不是独立验收：R2 间距<0.1mm+比例重叠可误删真实双线/尾段；R1 近共线写回会吞掉0.09mm真开口、0.9°真折角；P4 分隔线在单段斜线上自举误报（middlePlate 12 条），长度/bbox不等于有效分离线；P4 不足只 warn 会导致不可加工仍 exit0；样条 flattening(0.05mm)需单位/拓扑/二次运行验证。评审“不建议合main”。https://drive.google.com/file/d/1kdtEpJPtU0oWYHdbkG3Y7JDcozkieI3P/view
E. 第一次 10-15 网页/Windows CI 成功≠目标机器下载安装≠真实生产图能安全处理；用户已经表达不接受只展示样例。

## 四、第一阶段范围（优先保住 DXF 原图）
MUST：
1. 只读输入/原件留存+内容哈希；确定单位、缩放、嵌套 INSERT 变换、块颜色/图层继承、业务对象类型；未知单位或颜色加工含义不自动放行。
2. 严格保留所有非明确可等价删除的几何。近邻真实双边、部分重合独有尾段、碎线/分叉不自动整段删除；逻辑合并“完整直边”只用于选位，未经证实几何等价不改写加工轮廓。
3. 面向保留零件判断切割支撑关系，不用单个线段/bbox就断定独立零件/分隔线。内圈区分保留件/废料孔，语义不明待确认。禁止无权限给圆弧、装配槽底、尖角打口。
4. 按每件计算“要求几个/实际几个/位置合法吗/是否还有另一刀路切穿/挂在什么骨架上”；0或数量不足、分类有歧义、颜色未确认、原图破坏或导出重读失败统一不可生产，输出仅诊断。
5. 输出原图副本、新 DXF、整板+异常区高清局部图、逐件编号和报告（JSON+人看的），明示 rule version、input/output SHA256、板厚、颜色模板、导出兼容性、生产放行状态。
6. 复跑相同图不重复添加缺口；旧输出不得冒充最新执行结果。Windows H5 既有上传 API/界面继续使用，不再造第二套入口；开发只在 Draft PR 分支进行，main 不动。

OPTIONAL：AI/PDF/SVG/CDR 矢量颜色与加工映射（先人工确认并保留所有几何）、板幅分块（跨件/超尺寸件要诊断，不直接截断）、可登录外网版/微信机器人。
EXPERIMENTAL：SU 任意建筑自动拆模、全自动装配教程、从截图推断生产精确线稿；另立阶段，不绑架当前断口生产链。

## 五、最小回归和验收证据
- Golden：真实 3mm《最终版两个半张.dxf》人工位置对照图；5mm 佛光寺 v5 与原图；找不到原始 DXF 时状态 SOURCE_MISSING，不用网盘说明代替测试。
- 反例：双等长窄槽间距0.09/0.25mm、共线95%局部重叠带尾段、0.09mm真缝、0.9°微折角、碎直边、T分叉、1条/2条分隔线（含斜向）、开放斜线、弧线/槽底、纯曲线保留件、短边不足、旋转/镜像/缩放 INSERT、BYBLOCK/BYLAYER/true_color、TEXT/MTEXT/刻线遮挡、重复执行。
- 每个输出必须做几何差分、实际缺口宽和位置复查、DXF 审计+在目标加工软件打开预览，最终 3mm/5mm 试切，看是否挂得住、掰得下、能拼装。
- GitHub CI 自动测试通过只是“代码/构造图样例”层；最后生产放行需人工真实 DXF + 机器实切。
